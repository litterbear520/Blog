# 讲法骨架（课文版）

每课先判断它回答哪一类问题，再照对应的一行搭小标题。路线里 Stage 课文的结构以 `AGENTS.md`「路线页面」为准（上一课留下的问题 → 机制 → 演练 → 设计取舍 → 在本地运行），路线专题和 docs 课程照本表。

| 课型 | 回答的问题 | 小节顺序 | 常配的组件 |
| ---- | ---- | ---- | ---- |
| 概念课 | 是什么 / 为什么需要 | 导语一句定义 → X 解决的问题（具名场景 + 朴素方案的代价）→ X 的工作原理（4–6 步编号）→ 按需选：优势 / 边界 / 实现 / 何时使用 | 两个方案对照用两张同布局的 MessageFlow；实现用 McpWalkthrough |
| 机制课 | 怎么工作的 | 导语（和熟悉的东西对比）→ 核心问题 → 工作原理（编号步骤讲完整条链路，再放图复述）→ 按阶段分 H3，每阶段一张图 → 为什么这很重要 | 结构图（SVG）、MessageFlow 加 `upTo` 逐步展开、AgentLoopViz |
| 设计课 | 为什么这样设计 | 导语 → 问题 → 朴素设计及其代价 → 这个设计（演练逐步看真实代码）→ 取舍 → 何时该用、何时不该用 | McpWalkthrough、CardGrid 两栏“有 / 没有” |
| 对比课 | 区别在哪、该选哪个 | 成对的小节（各写做法、优势、缺点）→ 把选择收成一个判断问题 → 明确建议 | 成对小节就够；多维对照才用表格 |
| 直觉课 | 为什么会这样 | “X 更接近 A 而不是 B” → 成对演示 → 讲机制，点明优点和缺点出自同一个机制 → 失效方式与缓解（“把边界推远”） | 成对的 MessageFlow、CardGrid |

代码演练和讲解放在同一课：机制讲完，直接嵌 `<McpWalkthrough />`，一页读完。

## 通用讲法

口吻照 `docs/MCP` 课文：课程讲解口吻，用“我们”“您”，句子完整，每段先给结论再举例子，段落之间有过渡句。

- **导语。** H1 下一两段，不带标题：一句定义，或上一课留下的问题；再说这一课要解决什么。
- **具名场景。** 用一个有名字、有数字的具体场景引出问题（“商品 ID `P-999`”“读取 15 个文件”），名字和数字取自真实代码。先摆出朴素方案，说清它“可行，但……”的代价，再引出真正的设计。
- **编号步骤。** 机制写成 4–6 步编号列表，每一步主语完整（“执行器把结果……”）。
- **冒号引导。** 代码、图、列表、演练前面放一句以冒号结尾的引导句，说明接下来看什么。
- **粗体标签。** 优势、分类写成“**标签：** 一句解释”。
- **取舍句式。** “X 可以消除 Y，但会带来显著的权衡：**没有 A** —— 后果……不过，有一个好处：……”，最后落到“在以下情况下使用 X：”加条件。
- **一个比喻。** 每课至多一个，用“更接近 A 而不是 B”的句式轻轻带过。
- **预判反问。** 读者会冒出的疑问（“为什么不直接……？”）在它该出现的位置回答。
- **先文后图。** 先用文字讲完，再用图复述；图里每个元素都能在前文找到对应的一句。
- **小标题。** “主题 + 角度”的实词短语（“门控解决的问题”“一次加购怎样完成”“为什么这很重要”）。
- **结尾。** 最后一段点出本质，并把读者带到下一课要解决的问题；不加“总结 / 回顾”这类收尾标题。
- **版面克制。** 一节里至多一个组件或一张图；每课提示块至多两个，按含义选类型（标题写“提示”用 `:::tip`，写“注意”用 `:::warning`）。
