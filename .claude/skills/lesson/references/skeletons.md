# 课型骨架

一课先判断它属于哪一型，再照对应的小节顺序搭小标题。骨架都取自 `docs/MCP` 里的课文，括号里是范文；X 是这一课的概念名，写进小标题里。

## 概念课（Sampling、Roots）

回答“X 是什么、为什么需要它”，大多数课是这一型。

1. **导语**（不带标题）：一段两三句，X 是什么、怎么做到、带来什么后果。
2. **X 解决的问题**：“假设……”带出具名场景，痛点用一句转折点破（“但问题在这里——”）。常见做法是摆出两个选项：先给一个可行但代价大的做法，再给 X，两张同布局的图，各跟一段“**选项 1：**”“**选项 2：**”。
3. **X 的工作原理**（或 **X 的实际应用**）：一句“流程很简单：”或“以下是使用 X 后工作流程的变化：”，接 4–6 步，每步主语完整；前后配一张图，把这几步画出来。
4. **X 的优势**：粗体标签列表，三四条。
5. 按需加一节：**安全性与边界**、**实现方式**（一段 15 行以内、从快照里原样摘出的代码，只在代码的形状本身就是要点时放）。
6. **何时使用 X**：一句“在以下情况下……：”加三四条条件；最后一句点出本质。

## 机制课（STDIO 传输、深入理解 StreamableHTTP）

回答“X 是怎么一步步工作的”，主角是过程。

1. **导语**：一句话说明问题和这一课要看的过程。
2. **核心问题**：一个场景，说明朴素的做法卡在哪里。
3. **工作原理**：先用编号步骤把整条链路讲完，再按阶段分 H3，每个阶段一张图（时序图常用同一组参与者，每张只多一段消息）。
4. **为什么这很重要**（或 **关键要点**）：两三句，把这个过程和读者要做的判断连起来。

## 取舍课（状态与 StreamableHTTP 传输）

回答“什么时候该打开、什么时候该关掉”。

1. **导语**。
2. 一组递进的场景图：每张只比上一张多一个元素，图前一句冒号引导，图后一句说明变化。
3. 方案和它的代价：“设置 X 可以解决 Y，但……”，代价写成粗体标签列表。
4. **何时使用 X**：两组条件，各三四条。

## 以代码为主的概念课（日志和进度通知）

概念本身很简单、价值在怎么接入时用。

1. **导语**：两三段短段，依次讲价值、没有它时的痛点、启用后的样子。
2. **工作原理**：一段代码，加一个“关键方法”列表。
3. **另一端的实现**：一段代码，一两句说明。
4. **呈现方式选项**：粗体标签列表，按场景分。
5. 一句提醒收尾（“请记住，……完全是可选的”）。

## 演练页（采样演练）

紧跟在它讲的概念课后面；相邻两课读同一组代码时共用一页。

```mdx
---
description: 交互式练习：对照购物 Agent 的代码，逐步查看一次搜索怎样穿过工具边界。
---
```

- H1 是“概念名 + 演练”，页面只有这一句话和组件，不分小节。
- 步骤 4–8 步，按读者顺着代码走的顺序排：先看入口，再看调用到达之后发生什么。步骤标题是两到八个字的短语（“启动采样”“采样回调”“连接回调”），说明每步一两句，写法见 [读感](style.md) 末尾的例子。
