# 讲法目录

Academy 的课不是一个模子：MCP 课用两个选项对照讲概念，API 课从一个贯穿项目的缺口推出每个工具，Claude Code 课先讲骨架再讲部件，AI 能力课先让读者下注再展开，教程页每节都让读者先预测、再揭晓。一门课里各课的讲法也不一样。

写大纲时，每一课先判断内容属于哪一型（课型可以重复，相邻两课的开头、收尾和照的 Academy 课要不同；表里的小节顺序是这一型常见的顺序，收尾可以换成下面“收尾”里的任一种），再从下面挑开头、讲法、课内检查和收尾，并在大纲表里写明照的是 Academy 哪一课。原文抓取稿和截图在 `~/workspace/academy-research/`（`mcp-*`、`api-*`、`cc-*`、`cap-*`、`use-*`），每份 `*-report.md` 的第 2、3、8 节有更多例子。

## 课型

| 课型 | 回答什么 | 小节顺序 | 照 Academy 哪一课 |
| ---- | ---- | ---- | ---- |
| 概念课 | X 是什么、为什么需要 | 导语一段 →「X 解决的问题」（具名场景；常摆两个选项，先给可行但代价大的，两张图）→「X 的工作原理」（4–6 步；涉及几方往返或一个循环时，步骤后放一张图复述，Sampling、Roots 这一节就没有图）→「X 的优势」（粗体标签列表）→「何时使用 X」 | MCP《Sampling》《Roots》、API《工具使用简介》 |
| 骨架先行课 | 一个系统整体怎样运转 | 一句定位（和熟悉的东西对比）→ 骨架：编号步骤，后面放图复述 → 骨架用到的几样东西，每样一个 H2、一段话 →「回顾」一段把它们串起来 | Claude Code《Claude Code 的工作原理》 |
| 机制课 | 一个过程怎样一步步发生 | 导语 →「核心问题」→「工作原理」（先编号讲完整条链，再按阶段分 H3，每阶段一张图）→「为什么这很重要」 | MCP《STDIO 传输》《深入理解 StreamableHTTP》 |
| 项目框定课 | 这门课要做成什么、缺什么 | 目标（一句顾客原话）→ 为什么这有难度（列出几个缺口）→ 我们需要的工具（一个缺口对应一个工具，配图） | API《项目概述》 |
| 设计原则课 | 一条原则怎样落地 | 原则 → 正例和反例（“有 / 没有”双栏图）→ 落地做法或自检问题（“Claude 如何知道这个操作是否有效？”加几条做法） | API《智能体与工具》《环境检查》 |
| 取舍课 | 什么时候开、什么时候关 | 一组递进场景图（每张多一个元素）→ 方案和它的代价（粗体标签列表）→「何时使用 X」两组条件 | MCP《状态与 StreamableHTTP 传输》 |
| 对比课 | 两样东西区别在哪、该选哪个 | 成对小节，各写怎样加载或触发、“将 X 用于：”清单 → 把选择收成一个判断问题（“中间过程的工作重要吗？”）→ 明确建议 | 智能体技能入门《Skills 与其他 Claude Code 功能的比较》、API《工作流与智能体》 |
| 代码实操课 | 一段代码怎样一步步写出来 | 每节一句“以下是……：”→ 1–30 行代码 → 一两句解释；完整程序不整段出现，最后用“完整流程”编号列表收拢 | API《发送工具结果》《实现多轮》 |
| 直觉课 | 为什么会这样、什么时候会出错 | 先下注（快速检查）→ 一句“X 更接近 A 而不是 B”→ 成对演示（熟悉路径和边缘路径各一次）→ 说明优点和缺点出自同一个机制 → 失效方式和缓解（“把边界推远”） | AI 能力《下一个令牌预测》《工作记忆》《试一试：工作记忆》 |
| 动手教程 | 靠亲手试建立直觉 | 一个钩子问题 → 快速检查热身（不计分）→ 若干短节，每节一两段加一个让读者先预测再看结果的部分 → 阅读更多（支线）→「您现在可以做什么」自测清单 | 教程《令牌》《参数记忆与上下文》 |
| 演练页 | 在真实代码里找到讲的是哪几行 | 见下面“演练页” | MCP《采样演练》 |

## 开头

H1 下一行照 Academy 放课序和时长两枚标签：`<LessonMeta lesson={N} minutes={M} />`（全局组件，不用 import）。数字不自己估，照 `lesson_lint.py` 给的写：课序按目录里的文件编号数，时长按字数、图和快速检查算；演练页也放。导语接在它下面。

- **一句定义。** X 是什么、怎么做到、带来什么（MCP《Sampling》）。
- **一个具体提问，加一个失败的回答。** “如果有人问‘旧金山的天气怎么样？’Claude 只能回答‘很抱歉……’”（API《工具使用简介》）。
- **读者已有的体验，再一句反问推翻。** “信息越多意味着答案越好，对吗？并非总是如此。”（AI 能力《试一试：工作记忆》）
- **先下注。** 导语后、第一个小标题前放一道快速检查，答案顺势变成这一课的路线（教程《参数记忆与上下文》：“这三种情况都会发生，本课将按此顺序逐一讲解”）。
- **半句承接。** “编写完工具函数后，下一步是……”（API《工具模式》）；只说内容，不说课名。

## 讲法

- **两个选项对照。** 两张同布局的图，各跟一段“**选项 1：**”说明（MCP《Sampling》）。
- **同一张图先抽象、后具体。** 版面不动，只把标签换成具体场景（API《工具使用简介》）。
- **骨架先行。** 先用编号步骤讲完整条链，再放图复述，图上每个元素都能在步骤里找到（Claude Code《工作原理》）。
- **问题 → 机制 → 结果，再说代价。** “这正是子代理发挥作用的地方……结果是……”“代价是您失去了对子代理如何得出结论的可见性”（Claude Code 101《子代理》、子代理入门《什么是子代理？》）。
- **成对演示。** 同一种问法，一次落在熟悉区，一次落在边缘区，结果并排摆出来（AI 能力）。
- **换掉错误的心智模型。** 一句“X 更接近 A 而不是 B”，或换一个问法：“要问的不是……而是……”（AI 能力）。
- **先贴真实的失败产物，再讲修法。** 把一次错误的输出原样摆出来（API《链式工作流》）。
- **从玩具模型搭到真实系统。** 先用几条数据手算一遍，再说真实系统做的是同一件事（AI 能力《试一试：下一个令牌预测》）。
- **递进图组。** 每张图只比上一张多一个元素（MCP《状态》）。
- **点破不显眼的细节。** “只加载名称和描述，而不是完整内容。这是一个重要的细节。”（智能体技能入门《创建您的第一个技能》）
- **预判反问。** “您可能会想，为什么不……？关键在于……”（API《链式工作流》）。

## 课内检查

- **快速检查** `<QuickCheck>`：一道单选，当场判对错，每个选项都写解释，可以改选，不计分。放在导语后做热身，或放在一个机制讲完之后；一课至多两道。概念课、设计原则课这类 Academy 原本不放检查的课型，在“工作原理”一节末尾放一道（这一节的图本身就是答案时，题放在图前，先预测再看图）：题干用本课的具体场景，问“这件事归谁做”“这一项放在哪”，错误选项取课文里点破过的误解。组件自己会显示“答对了。”，正确选项的解释不再以“对。”开头。整门课末的概念评估另见 [课程结构](course.md)。
- **阅读更多** `<ReadMore title="读者会问的问题">`：边缘情况和支线收进去，主线不被打断（Claude Code《代码审查》、教程的“额外阅读”）。
- **小提示** `:::tip[小提示]`：主线之外的一条实用建议，放在一节末尾（Claude Code）。

## 收尾

同一门课里，按每课的课型选：

- **何时使用 X + 一句本质。** 一句“在以下情况下……：”加三四条条件，最后一句“X 本质上……”（MCP、API）。
- **回顾。** 一段把这一课的几样东西串起来，最后一句交代下一课为什么要学（“那个文件就是 CLAUDE.md，也是下一课的内容”，Claude Code）。
- **接下来。** 用一两个问题把下一课的主题说成悬念（AI 能力《下一个令牌预测》）。
- **关键要点** `:::important[关键要点]`：一两句结论，或按“定义 / 能做什么 / 在哪里失效”几条排（AI 能力、子代理课）。
- **自测清单。** “如果以下几句话对您都成立，您就掌握了这一课”，三四条“您能……”（教程）。
- **实际实施 + 一个自问的问题。** “在设计您自己的……时，请始终问自己：“……？””，接“这可能意味着：”加三四条做法，最后一句“X 将……从……转变为……”（API《环境检查》）。设计原则课常用。
- **格言。** “如果某件事必须每次都毫无例外地发生，不要把它放进提示里，把它放进 hook 里。”（Claude Code《Hooks》）
