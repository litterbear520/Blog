# 课程笔记

把用户的一个想法写成博客里的一门**课**：一组循序渐进的课文，每课先讲清问题、再讲机制，代码用演练逐步看，机制配图，整门课最后一篇概念评估。读者是用户自己，读起来要像在上一门好课。

## 输入

```text
/lesson roadmap/commerce-agents/工程化 Agent 工具
想法：想讲清什么、为什么想学
代码：../commerce-agents-dev（讲代码设计时给）
```

- **位置**：`docs/<分类>/…` 或 `roadmap/<项目>/…`，斜杠后面是课程名；推断不出来时停下来问。
- **规模**：大纲里三课及以上做成课程（索引页 + 课文 + 概念评估）；一两课写成单篇课文，不加测验。

## 步骤

1. **同步并读规矩。** `git pull --ff-only`。读 `AGENTS.md` 里目标位置对应的一节（「路线页面」或「MCP 课程笔记」，以及「内容编写规范」），再读目标目录里两三篇现有课文，看清口吻、小标题和组件用法。
   完成标准：能说出这个位置的专属规则，比如路线页面不提 Step 编号和 dev 仓库路径、不用 `run` 输出面板。
2. **读代码，找讲点。** 讲代码设计时读真实代码：入口、核心实现、测试。列出要讲的每个机制：它解决什么问题、实现在哪、一个具名场景（名字和数字取自代码）。
   完成标准：每个机制都有 `文件:行号` 和一个具名场景。
3. **出大纲表，等确认。** 课程写一张表：课名（中文，“主题 + 角度”）、课型（见 [讲法骨架](references/skeletons.md)）、每课的小标题、每节用的组件和图、演练取哪些文件；最后一行是概念评估。单篇课文只列小标题和组件。发给用户，确认后再往下写。
   完成标准：用户确认了大纲表，提出的改动都已改进表里。
4. **抽代码快照。** 演练里的代码不手抄：在 `tools/roadmap-sync/<配方>.config.mjs` 登记要展示的文件（没有配方就照 `commerce.config.mjs` 新建一个），跑 `npm run roadmap-sync -- <配方>`，生成的 `*.files.js` 一起提交，因为 CI 里没有源仓库。
5. **写课文和数据。** 文件结构照 [课程结构](references/course.md)，每课照 [讲法骨架](references/skeletons.md)，组件照 [组件怎么选](references/components.md)，图照 [出图规范](references/diagrams.md)，概念评估照 course.md 里的“概念评估”一节。
   完成标准：每课的小标题和大纲表一致，每个组件的数据都在注册表里登记了。
6. **补测试。** 新演练照 `tools/commerce-agent-loop-lesson.test.mjs` 写语义锚点测试，并加进 `tools/walkthrough-browser.mjs` 的 `lessons`；新消息流图登记后由 `npm run test:message-flow` 校验。推送前本地跑一遍 `npm run prebuild`，它就是 CI 构建前的全部测试（含代码查看器的白名单和布局测试）；布局测试要 Chrome，用 `CHROMIUM_BIN` 指定。
7. **自检。**
   - 每课第一段就是结论，或上一课留下的问题；小标题都是“主题 + 角度”，结尾不加收尾标题。
   - 演练和代码块里的代码都来自快照或真实文件；说明里提到的函数、字段、调用关系和触发条件，都能在代码里指到出处。
   - 每张图前有冒号引导句，图里的每个元素在前文都有对应的一句；图的说明文字写成一整句。
   - 引号用 “”；站内链接指向的文件和锚点都存在。
   - 路线页面的正文、演练说明和图里，都只用课名和 Stage 名指位置。
8. **提交、看 CI、看线上。** 提交信息用中文，按 `feat:` / `docs:` 前缀写改了什么，只描述改动本身；直接推 `main`，`gh run watch <id> --exit-status` 等 CI。部署后用浏览器打开线上页面，桌面宽度和 390 宽、深浅色各看一次，截图给用户。构建交给 CI（这台机器内存跑不动 `npm run build`）。

## 报告

- 改了哪些文件，新登记了哪些数据和测试；
- 和大纲表不一样的地方，以及原因；
- CI 结果，以及线上截图里值得用户看一眼的地方。
