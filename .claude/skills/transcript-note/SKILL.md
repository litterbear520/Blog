# 讲稿转笔记

目标：$ARGUMENTS（为空时向用户确认放在哪个目录、叫什么名字）。讲稿是用户在对话里贴的文本。

原则：**正文是用户的内容，只做最小替换**；可以加的是小标题、链接、代码块这类结构性内容，而且每一处都要在最后逐条告诉用户。

## 步骤

1. **同步并读周边。** `git pull --ff-only`；列出目标目录，读两三篇同目录的笔记，看清写法（标题、代码块 `title=` / `showLineNumbers=`、`<Term>`、链接习惯）。
   - 目录下没有 frontmatter 就不加；用到 MDX 组件（`import`、`<CardGrid>`）时存成 `.mdx`，否则存成 `.md`。
   - 放进子分组时，参照已有的 `_category_.json`。
   - 完成标准：列出讲稿里提到的、站内已有笔记的话题（“之前我们讲过……”“这个以后专门讲”），以及每个话题对应的文件。

2. **转写正文。** 逐段照抄讲稿，只做以下改动：
   - 涉及视频的说法改成文章：“这期视频”→“这篇文章”，“之前几期”→“之前几篇”，“视频里听到”→“文章里看到”，“技术视频”→“技术文章”。
   - 按语境修语音识别错误：同音字、断句、英文术语拼写（如 “GIL 呢，或者 GIL 以后” → “GIL 呢，我们以后”）。
   - 结尾如果是“点关注 / 一键三连”，整句去掉；其他结尾句保留。
   - 命令、文件名、标识符加行内代码。
   - 引号用 “”，不用「」。

   不润色口语，不删句，不加导语、提示块或总结；讲稿里过时的事实（版本号、star 数）不改。

3. **加小标题。** 照 `docs/MCP` 课文的写法，用“主题 + 角度”的实词短语，如“CPython 的不足”“PyPy 的速度与兼容性”“CPython 难以撼动的原因”。
   - 不用叙事型、比喻型标题，也不用“起点 / 方案”这类通用标签。
   - H1 是笔记名，结尾不加收尾标题。

4. **加链接。** 只挂在讲稿本身提到的事物上，而且必须读起来自然：
   - **链接落在中文短语上，行内代码留在链接外面。** 例如 `inspect` 的[官方文档]、`LOAD_FAST` 对应的 [C 代码]、`BINARY_ADD` 的[实现]、`StopIteration` 这个 [exception]。
   - 不要写 [`dis` 模块]、[`ceval.c` 的 `_PyEval_EvalFrameDefault`] 这种把代码包进链接的形式。句子里找不到合适的词可挂时，宁可不加链接。
   - **站内链接**：
     - “之前讲过的 X”“X 以后专门讲”链到对应笔记，用相对路径 `./xxx.md`、`../xxx.md`；
     - 需要跳到某一节时带锚点 `#小标题`，锚点按 github-slugger 规则生成：转小写，空格换成 `-`，去掉标点。例如 “其他 Python 实现” → `#其他-python-实现`。
   - **外部链接**：官方文档、项目主页、讲稿里“我们看这是某某官网给出的……”所指的页面。同一个目标只链一次，不给每个 API 名都配链接。
   - **反向补链**：旧笔记里有“之前的某一篇文章提到过”“以后有机会讲”指向本篇话题的，给那句话加上指向本篇的链接。

5. **代码与术语（按需）。**
   - 讲稿演示了完整、能独立运行的代码时，才加 `run` + `output`。输出用 `python3 xxx.py` 在本地实跑后录入，不加 `-u`。
   - 贴 CPython 源码时照已有笔记的写法：`` ```c title="Python/ceval.c" showLineNumbers=起始行 {高亮} ``。
   - 读者可能卡住的术语可以用 `<Term tip="...">词</Term>`（已全局注册）。
   - 纯科普、没有代码的讲稿，这一步跳过。

6. **自检。** 下面这条命令应当没有输出，否则说明还有把代码包进链接的写法：

   ```bash
   grep -rnoP '\[[^\]]*`[^\]]*\]\([^)]*\)' docs/
   ```

   逐个确认新加的站内链接和锚点对应的文件、小标题确实存在。

7. **提交并看 CI。** 不在本地跑 `npm run build`（本机内存不足）。
   - 提交信息用中文，格式如 `docs(python): 新增 CPython 笔记，GIL 笔记补上跳转`，末尾加 Co-Authored-By 尾注。
   - 直接推 `main`。
   - `gh run list -L 1` 拿到 run id，再用 `gh run watch <id> --exit-status` 等结果；失败时用 `gh run view <id> --log-failed` 查原因（多半是坏链接）。

## 报告

用中文，简洁：
- 改了哪些文件；
- 正文里所有不是照抄的地方，逐条列出（视频→文章的替换、识别错误的修正、加字）；
- 加了哪些小标题、哪些站内和外部链接；
- 讲稿里可能过时、但没改的事实，请用户决定是否加说明；
- CI 结果。
