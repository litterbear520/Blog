# 弱引用

我们来看一个程序。我们定义了一个非常简单的 `Player` 类，在它的 `__init__` 方法里，给每个玩家分配一个当前未使用的 `id`，同时把建立的玩家对象放到全局字典 `players` 里。

这个字典可能有很多用处，比如记录哪些 `id` 已经被使用，或者作为某种形式的缓存，用来找到对应的玩家。用全局字典或缓存字典保存对象，是一种很常见的做法。

## 缓存中的对象

接下来我们定义一个函数 `game`，表示一场游戏。每场游戏里面建立两个玩家，后面可能还需要让这两个玩家做一些事情，也可能会通过全局字典 `players` 查找玩家。这里的函数写得非常简单，只是拿来举例子。

我们需要在意的是：在 `game` 函数运行结束之后，这一场游戏的 `p1` 和 `p2` 就没有用了。下一场游戏开始的时候，建立的是两个全新的玩家对象。

```python run
players = {}

class Player:
    def __init__(self):
        for i in range(1000):
            if i not in players:
                self.id = i
                break
        players[self.id] = self

def game():
    p1 = Player()
    p2 = Player()

for _ in range(10):
    game()

print(players)
```

运行十场游戏之后，可以看到 `players` 里面保留了 20 个玩家对象，键从 `0` 到 `19`。我们一直在往这个字典里添加内容，却从来没有把用完的玩家移出去。尽管每次 `game` 调用结束之后，游戏已经不需要这两个玩家了，它们依然存活在字典里。

在 CPython 中，对象的回收主要依靠引用计数，同时也有处理循环引用的垃圾回收机制。这里虽然 `game` 结束之后，局部变量 `p1` 和 `p2` 不再持有玩家对象，但字典仍然对它们保持着强引用，所以它们不会被回收。[Python 3.13 数据模型文档](https://docs.python.org/3.13/reference/datamodel.html#objects-values-and-types)

随着游戏不断进行，字典里保留的对象也会越来越多。这个简化示例只尝试分配 `0` 到 `999`，没有处理编号耗尽的情况；这里先关注对象一直被字典保留的问题。

## 弱引用的作用

有什么解决办法呢？当然有。比如在 `game` 函数的最后，从 `players` 字典里把这两个玩家移出去；或者在每次游戏结束之后，把字典清空。

但是，当程序变得更复杂的时候，这些方案就很容易遇到问题。我们需要在各个退出位置记得清理，也不能随意清空其他游戏仍然需要的玩家记录。

我们期待的功能是：当一个玩家对象已经没有其他强引用的时候，字典就不再保留它。也就是说，如果只剩下这个缓存还保存着玩家，缓存不应该成为它继续存活的原因。

这是一个常用的需求，Python 也提供了对应的解决方案，叫作 **weak reference，弱引用**。

弱引用本身不会让对象继续存活。当对象不再有强引用时，它就可以被回收；弱引用并不构成它存活的条件。这正适合当前的场景：如果游戏的其他部分已经不再使用某个玩家，就允许这个玩家被释放。

与弱引用有关的功能在 `weakref` 模块里。这里先看两种基础且常用的弱引用字典。[Python 3.13 weakref 文档](https://docs.python.org/3.13/library/weakref.html)

## 对值使用弱引用

第一个是 `WeakValueDictionary`。它提供了类似字典的操作方式，但对每个值保持的是弱引用。当值所指向的对象被回收时，对应的键值对会自动从字典中移除。

和刚才的代码相比，我们把 `players` 换成 `weakref.WeakValueDictionary()`，玩家的创建和登记方式都不用改。为了让打印结果更清楚，打印时用 `dict(players)` 转成普通字典。

我们还在 `game` 函数的最后加了一次打印，然后运行两场游戏，最后在函数外再打印一次。

```python run {1,3-4,18,20,23}
import weakref

# players = {}
players = weakref.WeakValueDictionary()

class Player:
    def __init__(self):
        for i in range(1000):
            if i not in players:
                self.id = i
                break
        players[self.id] = self

def game():
    p1 = Player()
    p2 = Player()

    print(dict(players))

for _ in range(2):
    game()

print(dict(players))
```

```output exit=0 {3}
{0: <__main__.Player object at 0x1047ce510>, 1: <__main__.Player object at 0x104777b10>}
{0: <__main__.Player object at 0x104777b10>, 1: <__main__.Player object at 0x1047b8d60>}
{}
```

前两行分别是在两场游戏内部打印的，此时字典里还有玩家对象。最后一行是在游戏结束之后打印的，字典已经为空。

在 `game` 函数里面，`p1` 和 `p2` 还对玩家保持着强引用，所以玩家仍然存活。函数结束之后，这两个强引用消失，`players` 对值的弱引用又不会保留玩家，因此玩家被回收，对应的键值对也就自动移除了。

也正因为上一场游戏的记录已经移除，下一场游戏又可以使用 `0` 和 `1` 这两个编号。如果输出中出现了相同的对象地址，也不表示两场游戏使用的是同一个对象；对象释放之后，内存地址可以被后续对象复用。

这里的对象没有循环引用，在本例的 CPython 环境中会在函数返回后被回收。弱引用本身并不保证所有 Python 实现、所有场景都在同一个时刻回收对象。

## 对键使用弱引用

有 `WeakValueDictionary`，也有 `WeakKeyDictionary`。后者对字典的键保持弱引用，当键所指向的对象被回收时，对应的键值对也会被移除。

这次我们把 `players` 改成 `WeakKeyDictionary`，同时把登记玩家的语句改成 `players[self] = self.id`。也就是调换键和值，让玩家对象本身成为键，把它的 `id` 作为值。

```python run {3,11}
import weakref

players = weakref.WeakKeyDictionary()

class Player:
    def __init__(self):
        for i in range(1000):
            if i not in players:
                self.id = i
                break
        players[self] = self.id

def game():
    p1 = Player()
    p2 = Player()

    print(dict(players))

for _ in range(2):
    game()

print(dict(players))
```

```output exit=0 {3}
{<__main__.Player object at 0x104a2e510>: 0, <__main__.Player object at 0x1049d7b10>: 0}
{<__main__.Player object at 0x1049d7b10>: 0, <__main__.Player object at 0x104a18d60>: 0}
{}
```

可以看到，游戏内部仍能访问这些记录，但游戏结束后，字典依然被清空了。这次被弱引用的是作为键的玩家对象，而不是作为值的整数。

注意，这里沿用原来的编号分配代码后，两个玩家的 `id` 都是 `0`。因为 `if i not in players` 检查的是键，而现在的键已经变成玩家对象，整数 `0` 不在这些键里面，所以每次都会选中 `0`。这不影响示例演示弱引用的清理过程，但它已经不能保证编号唯一；如果实际采用这种映射方式，编号检查逻辑也需要相应调整。

### 自定义实例

普通的 Python 自定义类实例通常支持弱引用，但不能说所有用 Python 定义的对象都支持。常见的其他支持对象还包括 Python 函数、实例方法、集合和生成器。具体类型是否支持，可以查阅 [weakref 文档中的说明](https://docs.python.org/3.13/library/weakref.html)。

这里还有一个需要注意的地方：`__slots__` 会影响自定义类实例对弱引用的支持。

## `__slots__` 与弱引用

如果类定义了 <Term tip="声明实例可使用的属性槽位，例如 ['id']；通常能减少内存占用，并限制随意添加新属性。">{'__slots__'}</Term>，而且没有从父类继承弱引用支持，那么它的实例默认就不再支持弱引用。这里说的是类创建出来的实例，不是类对象本身。

### 限定实例属性

我们回到前面 `WeakValueDictionary` 的例子，只给 `Player` 增加 `__slots__ = ['id']`，其他逻辑保持一致。

```python run {6}
import weakref

players = weakref.WeakValueDictionary()

class Player:
    __slots__ = ['id']

    def __init__(self):
        for i in range(1000):
            if i not in players:
                self.id = i
                break
        players[self.id] = self

def game():
    p1 = Player()
    p2 = Player()

    print(dict(players))

for _ in range(2):
    game()

print(dict(players))
```

### 启用弱引用支持

在这种情况下，如果还想让实例支持弱引用，需要在 `__slots__` 里面增加 `'__weakref__'` 这一项。

```python run {6}
import weakref

players = weakref.WeakValueDictionary()

class Player:
    __slots__ = ['id', '__weakref__']

    def __init__(self):
        for i in range(1000):
            if i not in players:
                self.id = i
                break
        players[self.id] = self

def game():
    p1 = Player()
    p2 = Player()

    print(dict(players))

for _ in range(2):
    game()

print(dict(players))
```

```output exit=0 {3}
{0: <__main__.Player object at 0x104bae910>, 1: <__main__.Player object at 0x104bad850>}
{0: <__main__.Player object at 0x104bad850>, 1: <__main__.Player object at 0x104bae910>}
{}
```

加上之后，实例又可以被弱引用，游戏结束后字典也再次自动清空。

`__weakref__` 为实例提供了支持弱引用所需的空间。普通自定义类没有定义 `__slots__` 时，通常会自动获得这种支持；定义了 `__slots__`，又没有从父类继承这种支持时，就需要显式加上它。[Python 3.13 __slots__ 文档](https://docs.python.org/3.13/reference/datamodel.html#slots)
