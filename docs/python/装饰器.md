# 装饰器

这篇我们来讲 decorator，也就是装饰器。很多刚学 Python 的人会对这个概念感到迷茫，因为之前接触的语言可能没有这样的语法。网上的例子又往往同时出现嵌套函数、`*args` 和 `**kwargs`，哪怕是一个简单的功能，看起来也很复杂。我们先把这些内容拆开，逐步看清楚装饰器到底做了什么。

## 函数对象

讲装饰器之前，我们要先理清楚 Python 的一些基础知识。第一件事就是：函数是什么？在 Python 中，所有东西都是对象，函数也不例外。函数只是 Python 中的一个普通对象，也就是 object。

我们来看下面这几行代码编译之后的字节码。`dis.dis(s)` 会编译字符串中的代码并显示字节码，不会执行其中的 `print(double(2))`。

:::note[运行版本]
本文代码和预录输出使用 **CPython 3.13.12**。字节码属于 CPython 实现细节，不同版本的指令和显示格式可能不同；输出中的对象地址也会随运行变化。可对照 [Python 官方 dis 文档](https://docs.python.org/3.13/library/dis.html)。
:::

```python run
import dis

s = """
def double(x):
    return x * 2

print(double(2))
"""

dis.dis(s)
```


函数体被编译成了一个 code object，里面保存着函数的执行逻辑。注意输出中高亮的几行：`LOAD_CONST` 加载 `double` 的 code object，<Term tip="根据代码对象创建函数对象；创建函数时不会执行函数体。">MAKE_FUNCTION</Term> 创建函数对象，再由 <Term tip="把栈顶的对象绑定到当前命名空间中的指定名字。">STORE_NAME</Term> 将它保存到 `double` 这个名字下。

所以，当我们在 Python 中定义一个函数时，就是创建了一个函数对象，并把它绑定到一个名字。这里的 `double` 是引用函数对象的变量。当前版本并不需要像一些旧版字节码那样，在 `MAKE_FUNCTION` 前再单独加载函数名称。

## 可调用对象

函数对象有一个特点：它是一个 callable object，也就是可调用对象。我们可以在它后面加上小括号来调用它。这里定义的 `double` 需要参数 `x`，所以调用时还要传入一个参数。

从语法层面看，在一个表达式后面写调用括号，并不要求编译器先确定它一定可调用。如果运行时得到的对象不可调用，就会出错。比如下面这个 `1()`，它仍然可以被编译成字节码，不过编译器会发出 `SyntaxWarning`，提示这个整数不能被调用。

```python run
import dis

dis.dis("1()")
```

```output exit=0 {1,4,6}
<dis>:1: SyntaxWarning: 'int' object is not callable; perhaps you missed a comma?
  0           RESUME                   0

  1           LOAD_CONST               0 (1)
              PUSH_NULL
              CALL                     0
              RETURN_VALUE
```

注意高亮的部分：编译器仍然生成了加载整数 `1` 的 `LOAD_CONST`，以及尝试调用它的 <Term tip="调用栈上的可调用对象；如果对象不可调用，执行时会抛出 TypeError。">CALL</Term>。这里我们只是反汇编，所以进程正常结束；真正执行 `1()` 时，才会抛出 `TypeError: 'int' object is not callable`。

## 函数作为参数

理解了函数只是一个普通对象，就很容易理解：函数也可以作为参数，传进其他函数。

这里定义了 `double` 和 `triple`，它们都可以传给 `calc_number`。`calc_number` 的第一个参数 `func` 接收一个函数，第二个参数 `x` 接收一个数，然后执行 `func(x)`。

```python run
def double(x):
    return x * 2

def triple(x):
    return x * 3

def calc_number(func, x):
    print(func(x))

calc_number(double, 3)
calc_number(triple, 3)
```

```output exit=0
6
9
```

传入 `double, 3` 时，执行的是 `double(3)`，打印 `3 × 2`，结果为 `6`；传入 `triple, 3` 时，执行的是 `triple(3)`，打印 `3 × 3`，结果为 `9`。

所以函数完全可以像其他对象一样，被传来传去，被传进其他函数。注意传参时写的是 `double`，没有调用括号：我们传递的是函数对象本身。

## 函数作为返回值

同样，函数不光可以作为参数传进其他函数，也可以成为返回值。比如下面的 `get_multiple_func`，它本身是一个函数，返回的也是一个函数。返回的函数做什么事情，与 `get_multiple_func` 收到的参数有关。

```python run
def get_multiple_func(n):
    def multiple(x):
        return n * x

    return multiple

double = get_multiple_func(2)
triple = get_multiple_func(3)

print(double(3))
print(triple(3))
```

```output exit=0
6
9
```

这里稍微有点绕，我们分开看。`get_multiple_func` 接收参数 `n`，返回内层函数 `multiple`；`multiple` 接收参数 `x`，返回 `n * x`。

因此，`get_multiple_func(2)` 返回一个把输入值乘以 `2` 的函数，我们将它保存为 `double`；`get_multiple_func(3)` 返回一个把输入值乘以 `3` 的函数，我们将它保存为 `triple`。这两个函数仍然是 callable，可以像前面直接定义的函数一样使用。

调用 `double(3)` 和 `triple(3)`，输出依然是 `6` 和 `9`。`multiple` 能够继续访问外层的 `n`，用到的正是[闭包的实现机制](./闭包的实现机制.md)。这里的 `double`、`triple` 是两次调用分别创建的函数对象，并不是前面示例中定义的那两个对象，只是计算结果相同。

## 装饰器语法

如果你能理解函数可以作为参数，也可以作为返回值，那么装饰器就容易理解了。

首先要知道，装饰器本身是一个 callable，并没有特殊的对象类型。最开始可以把它理解为一个函数：`@` 后面跟的名字，就是这个函数名。我们先写一个极简的例子，定义函数 `dec`，然后在 `double` 上面加上 `@dec`。

```python run
import dis

s = """
def dec(f):
    pass

@dec
def double(x):
    return x * 2
"""

dis.dis(s)
```

```output exit=0 {7,9-10,12,14}
  0           RESUME                   0

  2           LOAD_CONST               0 (<code object dec at 0x100f2c030, file "<dis>", line 2>)
              MAKE_FUNCTION
              STORE_NAME               0 (dec)

  5           LOAD_NAME                0 (dec)

  6           LOAD_CONST               1 (<code object double at 0x100e95b50, file "<dis>", line 5>)
              MAKE_FUNCTION

  5           CALL                     0

  6           STORE_NAME               1 (double)
              RETURN_CONST             2 (None)

Disassembly of <code object dec at 0x100f2c030, file "<dis>", line 2>:
  2           RESUME                   0

  3           RETURN_CONST             0 (None)

Disassembly of <code object double at 0x100e95b50, file "<dis>", line 5>:
  5           RESUME                   0

  7           LOAD_FAST                0 (x)
              LOAD_CONST               1 (2)
              BINARY_OP                5 (*)
              RETURN_VALUE
```

上半部分是定义 `dec`，与普通函数的定义过程一样。装饰 `double` 时，注意高亮的几条指令：先由 `LOAD_NAME (dec)` 取出装饰器，再加载 `double` 的代码对象，通过 `MAKE_FUNCTION` 创建原函数对象。

接下来的 <Term tip="在这段字节码中，原函数占用隐式参数槽位，不计入 CALL 后的数字；CALL 0 仍会把它传给 dec。">CALL</Term> 才是应用装饰器的调用，它相当于执行 `dec(原函数对象)`。随后 `STORE_NAME (double)` 把调用结果保存到 `double` 这个名字下。这里的 `CALL` 是当前版本的指令，旧版本中可能会看到 `CALL_FUNCTION` 等不同名称。

因此，对于这个简单例子，`@dec` 可以理解为下面这种写法：先定义普通函数，再执行 `double = dec(double)`。

```python run
def dec(f):
    pass

def double(x):
    return x * 2

double = dec(double)
```

```output empty

```

这段代码展示的是去掉 `@dec` 后的写法。两种形式任选一种；如果已经写了 `@dec`，再执行一次 `double = dec(double)`，就会再次调用装饰器。

这里的 `dec` 只有 `pass`，会隐式返回 `None`，因此装饰后的 `double` 也是 `None`。这个例子只用来观察装饰器的语法；它没有保留原函数供后续调用。

装饰器会在执行函数定义时应用，而不是等到我们调用 `double()` 时才应用。Python 官方文档也用这种调用后重新绑定名字的方式解释[函数装饰器](https://docs.python.org/3.13/reference/compound_stmts.html#function-definitions)。

## 装饰器的返回值

通常我们会说，装饰器是一个接收函数、返回函数的函数。但返回值一定要是函数吗？还真不一定。为了帮助理解，我们看一个返回整数的例子。

```python run
def dec(f):
    return 1

@dec
def double(x):
    return x * 2

print(double)
```

```output exit=0
1
```

注意，我们打印的是 `double` 这个变量本身，并没有执行 `double(2)` 或 `double(3)`。结果为什么是 `1`？把它改写成不使用 `@` 的形式，就很清楚了。

```python run
def dec(f):
    return 1

def double(x):
    return x * 2

double = dec(double)
print(double)
```

```output exit=0
1
```

`dec(double)` 返回 `1`，`1` 被赋值给 `double`，所以打印结果就是 `1`。这时 `double` 已经不是函数，也不能再被调用。

这个例子说明，`@` 语法会把装饰器的返回值绑定到原来的名字，并不要求返回值仍然是函数。当然，绝大多数用于包装函数的装饰器，仍然会接收一个函数，再返回一个函数。

这里讨论的是函数装饰器。装饰器也可以用于类；如果叠加多个装饰器，外层装饰器接收到的是内层装饰器的返回值，因此也不能笼统地说装饰器的输入一定是函数。

## 函数计时

回到常见的计时例子。为了先看清楚结构，我们暂时不使用 `*args` 和 `**kwargs`，让包装函数只接收一个参数。

```python run
import time

def timeit(f):
    def wrapper(x):
        start = time.time()
        ret = f(x)
        print(time.time() - start)
        return ret

    return wrapper

@timeit
def my_func(x):
    time.sleep(x)

my_func(1)
```

```output exit=0
1.003727912902832
```

`timeit` 是一个函数，我们把它当作装饰器使用。它接收的 `f` 是原函数，返回的 `wrapper` 也是一个函数。

`wrapper` 和 `my_func` 一样，都接收一个参数。它先记录开始时间，再调用 `f(x)` 并保存返回值，接着打印耗时，最后把原函数的返回值返回。

加上装饰器之后，名字 `my_func` 引用的是 `wrapper`。调用 `my_func(1)`，会通过 `wrapper` 执行原函数中的 `time.sleep(1)`，并打印大约一秒的耗时。原函数本身没有显式返回值，所以 `wrapper` 最终返回的是 `None`；这里没有用 `print` 打印这个返回值。

:::note[计时输出]
代码按原示例使用 `time.time()`，将调用前后的时间相减，得到以秒为单位的耗时。预录输出来自实际运行，每次执行的具体数值都会不同。
:::

### 复用装饰器

使用装饰器的好处是，不同函数需要同一项功能时，可以用同样简洁的方式完成。比如再定义一个 `other_func`，返回 `x * 2`，也给它加上 `@timeit`。

```python run
import time

def timeit(f):
    def wrapper(x):
        start = time.time()
        ret = f(x)
        print(time.time() - start)
        return ret

    return wrapper

@timeit
def my_func(x):
    time.sleep(x)

@timeit
def other_func(x):
    return x * 2

print(other_func(2))
```

```output exit=0
0.0
4
```

这次输出有两行：第一行是 `wrapper` 打印的函数耗时，第二行是外面的 `print(other_func(2))` 打印的返回值 `4`。包装函数添加了计时功能，同时把原函数的返回值传了出来。

## 可变参数

接下来再看常见的完整写法：为什么 `wrapper` 使用 `*args` 和 `**kwargs`？

刚才的 `wrapper(x)` 只能转发一个位置参数。如果被装饰函数有多个参数，就需要让包装函数接收它们，再原样传给原函数。

```python run
import time

def timeit(f):
    def wrapper(*args, **kwargs):
        start = time.time()
        ret = f(*args, **kwargs)
        print(time.time() - start)
        return ret

    return wrapper

@timeit
def my_func(x):
    time.sleep(x)

@timeit
def add(x, y):
    return x + y

print(add(2, 3))
```

```output exit=0
9.5367431640625e-07
5
```

在函数定义中，`*args` 收集位置参数，`**kwargs` 收集关键字参数；调用 `f(*args, **kwargs)` 时，再将它们解包传给 `f`。关于解包，可以结合[基础笔记](./基础.md)中对应的小节阅读。

这样，调用 `add(2, 3)` 时，两个参数就能正确传给原函数。第一行打印耗时，第二行由外面的 `print` 打印结果 `5`。`**kwargs` 同样可以转发关键字参数，但传入的参数仍然需要符合原函数的要求。

## 带参数的装饰器

再进阶一步：如果装饰器本身也带参数，又是怎么回事？它只是在应用装饰器之前，多了一次函数调用。

不带参数时，`@timeit` 对应的是 `double = timeit(double)`。带参数时，比如 `@timeit(1000)`，要先计算 `timeit(1000)`，取得真正的装饰器，再用它装饰原函数。

原来的 `timeit` 接收函数，返回包装函数。现在最外层的 `timeit` 接收我们指定的配置，返回一个函数 `inner`；这个 `inner` 才是之前那种接收函数、返回包装函数的装饰器。

### 重复计时

下面的 `iteration` 表示运行次数。`inner` 接收原函数 `f`，返回 `wrapper`；`wrapper` 则在计时期间运行 `iteration` 次原函数。

```python run
import time

def timeit(iteration):
    def inner(f):
        def wrapper(*args, **kwargs):
            start = time.time()
            for _ in range(iteration):
                ret = f(*args, **kwargs)
            print(time.time() - start)
            return ret

        return wrapper

    return inner

@timeit(1000)
def double(x):
    return x * 2

double(2)
```

```output exit=0
4.00543212890625e-05
```

这里有三层函数，它们分别接收不同的参数：

| 函数 | 接收的参数 | 返回的内容 |
| ---- | ---- | ---- |
| `timeit` | 运行次数 `iteration` | 装饰器 `inner` |
| `inner` | 原函数 `f` | 包装函数 `wrapper` |
| `wrapper` | 原函数的调用参数 | 最后一次调用 `f` 的返回值 |

### 调用过程

上面的 `@timeit(1000)` 可以展开为下面的形式。这是局部改写示意，需要使用前面已经定义的 `timeit`；不要把它追加到已经装饰过的 `double` 后面。

```python
inner = timeit(1000)

def double(x):
    return x * 2

double = inner(double)
double(2)
```

先执行 `timeit(1000)`，拿到 `inner`；然后 `inner` 接收原来的 `double` 函数，返回 `wrapper`，并将这个返回值保存到名字 `double` 下。这对应的简写就是 `double = timeit(1000)(double)`。

直到调用 `double(2)` 时，才真正进入 `wrapper`，执行计时和循环。输出是循环调用原函数 1000 次的总耗时，包含循环和调用开销，并不是单次运行时间。`double(2)` 仍然返回最后一次调用的结果 `4`，但原示例没有用 `print` 打印它，所以输出只有耗时。

这个示例约定 `iteration` 为正整数，并返回最后一次调用的结果。因为原函数确实会重复执行，函数里的其他操作也会重复发生。对于这里的 `double`，每次只做乘法，所以很容易观察计时和返回值。
