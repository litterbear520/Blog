## iterable 与 iterator

在 for loop 的实现背后呢，有两个核心概念：一个叫可迭代对象，一个叫迭代器。那么英文分别是 iterable 跟 iterator。我们先来看一下 Python 官网上给这两个词下的定义。

那 [iterable](https://docs.python.org/3.10/glossary.html#term-iterable)，也就是可迭代对象，它说的是一个对象，然后可以一个一个地返回它的成员。它给了一些例子，对吧？比如说 list、string、tuple，包括 dictionary。然后它也特别强调了，对吧，这个 iterable 可以在 for loop 里面使用。

当然确切地说呢，是 for loop 里面 `in` 后面那个东西必须是一个 iterable，也就是必须是一个可迭代对象。这件事儿不难理解，对吧？因为 for loop 就是在那个对象里面一个一个拿出它的成员来。它们两个定义几乎是完全重合的。这也是为什么我们要把 for loop 跟这个可迭代对象放到一起讲。

那我们再看 [iterator](https://docs.python.org/3.10/glossary.html#term-iterator)，也就是迭代器。iterator 是一个表示数据流的对象，你可以使用 `next` 函数不断地从这个对象里面获取新的数据。那这两个概念确实有很多相似的地方，但是如果你想把这块的理论全都搞明白的话，你就必须要分清它们俩有什么区别。

### 数据与状态

从一个 high level 的角度看，一个 iterable 更像是一个数据的保存者，一个 container。它是可以没有状态的，它可以完全不知道你这个 iterator 数到哪了。它需要有能力产生一个 iterator，而 iterator 一定是有状态的，但是它并不需要实现一个 container。它当然内部肯定知道它代表这个 iterable 里面是什么数据，但是它不用实现一个 interface，不用实现一个接口来修改这个 iterable 里面的数据。

### `__iter__()` 与 `__next__()`

从实现上看，一个 iterable 要么就有 `__iter__()`，要么就有 `__getitem__()`。这两者都是为了保证它可以在 `iter` 这个[函数](https://docs.python.org/3.10/library/functions.html#iter)的作用下返回一个 iterator。而 iterator 必须要有 `__next__()` 这个 method，这个 method 保证它在被 `next` 作用的时候可以返回下一个 iterable 里面的值。

在 `LOAD_NAME` 之后，它做了一个 `GET_ITER`，而 `GET_ITER` 这个 [bytecode](https://docs.python.org/3.10/library/dis.html#opcode-GET_ITER)，就是从栈顶的这个 iterable 里面拿出来它所对应的 iterator。所有的 for loop 的实现都是这样的。

```c {4,6}
case TARGET(GET_ITER): {
    /* before: [obj]; after [getiter(obj)] */
    PyObject *iterable = TOP();
    PyObject *iter = PyObject_GetIter(iterable);
    Py_DECREF(iterable);
    SET_TOP(iter);
    if (iter == NULL)
        goto error;
    PREDICT(FOR_ITER);
    PREDICT(CALL_FUNCTION);
    DISPATCH();
}
```

所以你可以理解为，当你写一个 `for` 什么 `in` 一个 iterable 的时候，for loop 首先悄悄地做了一个从 iterable 里面拿到 iterator 的操作。你可以把它想象成下面这个样子。

## 让 iterator 也是 iterable

好，那可能很多人看到这里会产生一个疑问，就是我看到的所有教程里，这个 iterator 除了 `__next__()` 函数之外，还要实现这个 `__iter__()` 函数，为什么你这里没实现呢？我们看回 Python 的[官方文档](https://docs.python.org/3.10/library/stdtypes.html#iterator-types)，官方文档这也说，说 iterator 必须要有这个 `__iter__()` method。当然它也把这么规定的原因写明白了。它说这么做是为了让每一个 iterator 也是 iterable，就是让每一个迭代器也是可迭代的。

### CPython 的实现细节

当然了，如果你看回 [CPython 文档](https://docs.python.org/3.10/glossary.html#term-iterator)的话，你会发现它下面写了一行话，叫做 CPython 本身也并不总是遵循每一个 iterator 都是 iterable 的要求。你说这些人讨厌不讨厌，自己定了一个要求，自己不遵守。

那对于 iterator 到底需不需要有 `__iter__()` 这个函数，或者是需不需要 iterable 这个事，我的观点是，首先最好写，因为这件事很简单，就两行代码。但是更重要的应该是，你应该知道 `__iter__()` 这个函数是干嘛的，`__next__()` 这个函数是干嘛的，它们俩有什么区别。也就是你要分清什么是 iterable，什么是 iterator，这两个东西是不一样的。如果你能理解它们两个有什么区别，那到底谁要写 `__next__()` 函数，谁要写 `__iter__()` 函数，就非常一目了然了。
