# 类装饰器

在之前一篇文章里，我们介绍过这个[装饰器](./函数装饰器.md)，也就是 decorator。在那篇文章里，我说这个装饰器就是一个输入是函数、输出也是函数的这么一个函数。那这个定义，其实它并不完全准确。这么说，只是让刚入门装饰器的人可以理解它的核心理念。

那在那篇文章的留言里，就有人让我讲一下类装饰器。那包括后面，也有很多人通过留言或者私信的方式，让我讲一讲这个类装饰器。所以这篇文章，我们就讲一下装饰器和类之间的爱恨纠葛。

那“类装饰器”这个词，包括它的英文 class decorator，实际上是有一定的歧义的。在有的地方，它是指可以当作装饰器的类；那在有些地方，它是指可以装饰类的装饰器。那这其实是两个正交的概念：一个聊的是装饰器本身，一个聊的是装饰器要装饰的对象。

那么通过今天的文章，你就可以知道，装饰器本身既可以是函数，也可以是类；而装饰的对象，同样既可以是函数，也可以是类。所以你要弄懂的是它背后的核心机制和理念，而不是一个一个的组合去硬背。

## 装饰器的等价形式

那问题来了，这个 `Timer` 类究竟是怎么作为一个装饰器起作用的呢？那可能很多教程就要让你在这背了，对吧？一个类作为装饰器要怎么样，一个函数要怎么样，后面加了 argument 要怎么样。但是今天我教给你，你只需要记住一条万能公式，这些东西你全都不用背，就是这个装饰器语法糖背后真正的等价形式。也就是 13 行这个 `@Timer` 究竟做了什么。

而在上篇文章里面，这件事我[讲过](./函数装饰器.md#装饰器语法)：在一个函数上做装饰器，就等价于这个函数名等于装饰器调用这个函数。也就是说，第 13 行的 `@Timer`，它就相当于在后面运行了一个 `add` 等于 `Timer` 括号 `add`。那如果你能把它转换成这个形式的话，你是不是就立刻可以明白到底发生什么事了？

<CodeWalkthrough variant="timerClass" step={2} />

这个装饰器相当于把 `add` 从一个函数变成了一个 `Timer` 类的对象。因为我做了一个 `Timer(add)` 嘛，`Timer` 是一个类，对不对？它相当于建立了一个这个类的对象。然后 `add` 被传进了它的 `__init__` 函数里，`__init__` 函数呢，take 一个 `func`，对不对？所以 `add` 作为一个参数被保存在了 `self.func` 里，然后整个这个 `Timer` object 被保存在了 `add` 这个名字里。

那接下来第 20 行 `add(2, 3)` 的时候，它实际上是调用了这个 `Timer` object 的 `__call__` 这个函数，它相当于做了一个对象的调用。那这个时候呢，2 跟 3 就被传到了这个 `__call__` 里面。所以它就运行了 `start` 等于时间，然后拿到一个 return value。`self.func` 就是原来的 `add` 函数，对不对？它就把 a 跟 b 加起来，然后返回到了 `ret` 里，然后打印了消耗的时间，再返回这个值，最后这个值再被 print 出来。

可以看到，它跟我们之前讲的函数 decorator，其实没有很大的区别。原来的函数装饰器呢，是函数调用一个函数，返回一个函数。更确切地说呢，是函数调用一个函数，返回一个 callable。那现在呢，是类调用一个函数，返回一个 object，它依然是一个 callable。你只需要把这个 decorator 在脑海中，转化成下面这个等价形式，你就非常容易理解了。我们甚至还可以在这里打印一下 `add` 的 type，可以看到，`add` 就是一个 `Timer` object。

这时候你可能会想了，对吧？这个装饰器能给函数用，怎么还能给 class 用呢？它们之间有什么不同吗？每当你遇到装饰器感到迷茫的时候，你只需要把它换成它的等价形式。

<CodeWalkthrough variant="addStr" step={2} />

我们来换一下。我们知道，在 Python 中，定义的 class 本身它也是一个 object。那么第 7 行的 `add_str`，就相当于 14 行的 `MyObject` 等于 `add_str(MyObject)`。也就是 `add_str` 这个函数，是一个参数是 class、返回值也是 class 的函数。那我们再往上看这个 `add_str` 的 definition，它的参数是一个 class，`cls`，对不对？它的返回值是原封不动地返回了这个 class。只不过它在第 4 行的时候，把 class 的 `__str__` 函数给替代成了它自定义的 str 函数。而它定义的这个 str 函数，是返回 `self.__dict__` 的 str 形式。也就是说，这个 decorator 本质上就是重载了一下这个 class 的 `__str__` 函数。

那如果你能把它成功地想象成这个等价形式的话，你就会发现，给类写装饰器也没有什么难的嘛。它就是输入一个类，返回一个类嘛。然后我在这个类上动动手脚，完成我需要的事情就可以了。

当然，同样的，这个装饰器也是可以传参数的。如果你弄不懂的话，依然是把它写成等价形式，然后再去想，我这个函数的返回值应该是一个什么。那样的话，这个函数的返回值就应该是一个函数了，而返回的这个函数，参数是一个 class，返回值是一个 class。

那通过今天这几个例子，大家应该可以感受到，不管是 decorator 本身，还是它装饰的对象，不管它们是函数还是类，只要你可以把它转换成等价形式，它都是比较好读的。而转换成等价形式之后，你就知道我需要写一个什么东西，它的输入应该是什么，它的输出应该是什么。就再也不用照着网上教程抄，然后还不知道对不对了。
