# 少写 for 循环

这篇文章我们要讲的内容跟 `for` 有关。大家知道，在 Python 里面，for loop 是一个非常非常重要而且常用的结构。但是我们今天要给大家讲的是如何少写 for loop。当然，我不是说写 for loop 就是错的，或者你能少写就少写，而是说在有一些情况下，我们可以用 Python 的一些 feature，或者 [built-in functions](https://docs.python.org/3/library/functions.html)，让你的代码在不使用 for loop 的情况下，实现同样的效果，并且更快、更整洁。

## built-in 的 max 与 min

接下来我们要介绍的是两个非常简单的 built-in 函数，`max` 和 `min`。这两个函数非常容易理解，分别是求 iterable 里面的最大值和最小值。为什么要聊这么简单的函数？是想让大家知道一下，built-in 函数的速度和你自己写的 Python 速度差多少。我们知道，求最大值是一个非常简单的事情，它也没有任何 fancy 的算法，它只能一个一个拿出来比大小。也就是说，算法层面上，我们这里已经写的是最简单的算法了。而我们运行一下就会发现，Python 自带的 built-in 的 `max` 比我们自己实现的 `max` 要快了一倍。

<CodeWalkthrough variant="lessFor" step={5} />

那这个速度的差距，主要是因为我们在运行 Python 代码的时候，这些[字节码](./虚拟机.mdx#字节码与栈)带来的 overhead。比如说，当我们把变量保存进一个 local 的临时变量的时候，再比如说，我们判断然后 branch 的时候，当我们运行这些 Python 的 bytecode 的时候，我们实际上花费了很多不必要的时间。而在 CPython 用 C 实现的 `max` 里，尽管我也需要从这个 Python object 里面一个一个往外拿东西，但是在保存、循环、判断的时候，我都可以在 C 层面进行，因此就抢出了很多的速度。那这个也是 Python 优化的第一个技巧，就是能用 built-in 函数完成的代码，不要用 Python 写。

## 用 any 查找满足条件的值

好，那接下来我们介绍两个稍微不那么常见的函数，一个叫做 `any`，一个叫做 `all`。我们看这段 Python 代码，这也是我们很常见的一个 pattern，就是我们找遍一个 list，然后如果发现一个什么样的东西，直接 `return True`，否则的话 `return False`。比如说，我想找找这个 list 里面有没有一个大于 50 的数。对于这种在一个 iterable 里面寻找有没有一个这样的东西的任务，我们可以用 `any` 来完成。

<CodeWalkthrough variant="lessFor" step={6} />

大家注意这个 `any` 里面，我直接写了一个非常像 list comprehension 的东西，它实际上是我们刚刚提到的 generator。你可能说不对呀，这个括号对不上，对吧？这个 generator 应该是长成下面这个样子的，对吧？

```python
any((num > 50 for num in lst))
```

这个里面 generator 本身有一个括号，然后外面函数调用再有一个括号，它应该是两层括号。那这里就是 Python 的一个小小的[语法糖](https://docs.python.org/3/reference/expressions.html#generator-expressions)。当你把这个 generator 本身当做一个 argument 传进函数里的时候，generator 的那个括号就会不用写了，这样让你的代码会看起来更整洁一些。

## any 的可读性与速度

好，我们看这两种写法的对比，明显是用 built-in 函数的写法在语义上更清晰，用人话来说就是可读性更好。但是这里注意一下，如果你运行一下 benchmark，你会发现，使用 `any` 会比直接写 Python 还要慢一些。这里的原因是我们这个 generator 本身，还是运行在 Python 层面的，所以这个不用 `any` 的代码要做的东西，我们基本上都做了。而 generator 的建立和调用本身，它是有代价的，所以使用 `any` 的时候反而更慢了。事实上，如果我们没有这个 generator，而是直接在一个 list 里面找 `True` 的话，`any` 是比 Python 的写法要快的。那我个人还是会更喜欢用 built-in 函数这个写法，因为它的可读性是更好的。

## any 与 all 里用 generator 而不是 list

这里我们注意一下，如果我们在使用 `any` 的时候，传进去的是一个列表表达式，那它的速度又会明显地更慢一些。

<CodeWalkthrough variant="lessFor" step={9} />

为什么呢？因为对于 `any` 来说，它只要看到一个满足题意的就可以返回了。也就是如果你使用 generator 的话，它不需要把 list 里面每一个东西都拿到。而如果你用 list comprehension，它就需要先把整个 list 过一遍，然后再把这个 list 传给 `any`，那这样就显然慢了。所以当我们在使用 `any` 或者 `all` 的时候，一定要记得使用 generator，而不用 list comprehension。

## 用 filter 筛选

好，那我们接下来介绍一些稍微有一点难度的用法。假如说我有一个 list，同时我还有一个判断函数，来判断一个值我想不想要，然后我想找到这个 list 里面所有满足我这个判断函数的值。比如说在现在这个程序里面，我想找到这个 list 里面所有大于等于 60 的数。那传统的写法非常直观，过一遍 list，如果这个判断成立的话，我加进去，最后把这个返回的 list 给返回。那实际上你完全可以用 list comprehension 来实现这个事情。你只需要在我们之前讲的 list comprehension 后面加一个 condition，加一个 `if`，也就是只有 `good(num)` 的时候，才把这个 `num` 放到这个 list 里。

<CodeWalkthrough variant="lessFor" step={10} />

但是呢，在这里我们也介绍一个使用 built-in function 的方法。我们可以使用一个 `filter` 函数。`filter` 函数的第一个 argument 是一个判断函数，第二个 argument 是一个 iterable。它会从这个 iterable 里面把所有的值拿出来，然后拿这个判断函数判断一下，和我们刚才说的是同一个功能。

<CodeWalkthrough variant="lessFor" step={11} />

这里要注意一下，`filter` 这个函数返回的并不是一个 list，而是一个 generator。也就是说，它并不等价于我们刚才的 list comprehension，它基本等价于把刚才的那个 list comprehension 里面的方括号变成圆括号，也就是 generator。唯一一个小小的不同是，如果它的第一个 argument 传进去的是 `None` 的话，它就会把这个 list 里面所有 evaluate 成 `False` 的东西给剔除。那你是更喜欢写 list comprehension 或者 generator，还是更喜欢用这个 built-in function，就要看你自己觉得哪一种语义对你来说更可读了。

:::info
严格来说，`filter`、`map`、`zip` 返回的是[迭代器](./迭代器.mdx)，`type` 分别是 `filter`、`map`、`zip`，并不是 generator 对象。不过用起来和 generator 一样，都是每次 `next()` 才算出一个值，而且只能遍历一次：`m = map(str, lst)` 之后，第一次 `list(m)` 得到 `['1', '2', '3']`，第二次就是 `[]` 了。要反复使用结果，可以先用 `list(...)` 存下来，或者重新调用一次 `map(str, lst)`。
:::
