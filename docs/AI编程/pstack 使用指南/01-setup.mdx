# 安装和配置 pstack

在这一章里，您会安装 pstack 插件、选定它要使用的模型，并跑通第一个任务。整个配置只需要一条命令，再加上几轮简短的对话。

## 安装插件 {#install-the-plugin}

在 Cursor 对话框中运行：

```text
/add-plugin pstack
```

Cursor 会提示插件已安装完成。

如果您在 Claude Code 里使用，请依次运行 `/plugin marketplace add cursor/plugins` 和 `/plugin install pstack@cursor-plugins`。Claude Code 会给所有插件命令统一加上 `pstack:` 前缀，因此本指南里出现的所有命令在 Claude Code 中都要写成带前缀的形式——例如 `/setup-pstack` 要写成 `/pstack:setup-pstack`，后文的 `/poteto-mode` 也要写成 `/pstack:poteto-mode`。运行 `/pstack:setup-pstack` 后，它会把模型规则写入 `~/.claude/rules/pstack-models.md`。其他差异见 [Claude Code 适配说明](https://github.com/cursor/plugins/blob/main/pstack/docs/harness/claude-code.md)。

## 选择模型 {#pick-your-models}

运行：

```text
/setup-pstack
```

[`/setup-pstack`](https://github.com/cursor/plugins/blob/main/pstack/skills/setup-pstack/SKILL.md) 会检测您当前有权访问的模型，询问您想用的推理预算，然后逐一展示各个角色（写代码的子代理、负责判断的角色、评审组）并询问您的偏好。回答这些问题即可。它会生成 `~/.cursor/rules/pstack-models.mdc`——一份简短的规则文件，pstack 里的每个技能都会读取它。

默认配置等同于 `large` 推理预算：写代码、写文字和做判断这几个角色使用 `xhigh` 推理等级的 Opus 5.5，评审组和 `/swarm` 的 <Term tip="worker：被派去完成其中一份工作的子代理，各管一片、各自汇报">worker</Term> 使用 `high` 等级。没有任何角色会超过 `xhigh`。在评审组之外，只有在您为任务明确点名 Fable 5.2，或者 Opus 5.5 对同一份任务说明连续跑了两次都没通过检查时，才会改用 Fable 5.2。`medium` 会把每个角色的推理等级往下降一档，`small` 会降两档，两者都更省 token。

您只需要覆盖自己关心的角色。规则文件里没有写明的角色，会沿用技能自带的默认值；想恢复默认，把对应那一行删掉就行。重新运行 `/setup-pstack` 时，凡是您改成了非默认模型的角色都会原样保留。如果 pstack 日后调整了默认模型，旧规则文件里写死的还是之前的默认值，直到您再次运行 `/setup-pstack`。重跑时，它会替换掉能认出来的旧默认值、告诉您改了哪几项，同时保留您的其他选择。如果有某个写死的旧配置它认不出来，您先删掉对应的那一行，或者先删掉整个规则文件再重跑就行。

您可能会好奇，如果平时用的是 Auto 模式会怎样。只要把某个角色设为 `inherit-parent` 或 `auto`，pstack 在派发子代理时就不会传 `model` 字段，子代理会直接继承当前主对话的模型。这两个值意思完全一样，都不是具体的模型标识名。评审组角色的值是一个列表，列表里每写一项就会启动一个子代理，所以列表长度决定了评审组的人数。配置过程还会设置 `swarm workers` 这一项，用来指定 `/swarm` 下各个 worker 的默认模型。如果某次多路竞速给每条路线单独指定了模型，就以那次指定的为准。

## 要不要生成验证技能 {#accept-the-verification-offers-or-dont}

配置快结束时，`/setup-pstack` 会在您的项目里寻找能证明应用行为的手段——要么是一个 `verify-*` 技能，要么是一套现成的 <Term tip="驱动和检查应用的现成脚本或工具">harness</Term>。如果两样都没找到，它会主动问您一次，要不要用 [`/create-verification-skill`](https://github.com/cursor/plugins/blob/main/pstack/skills/create-verification-skill/SKILL.md) 生成一个。

如果您选“是”，它会在 `.cursor/skills/verify-<app>/` 下写入一个项目本地技能（只属于当前项目的技能），教 Agent 像真实用户那样驱动您的应用，并在交付前先实跑一遍，证明这个验证技能确实能用。如果您选“否”，配置就会直接跳过这一步。您随时都可以自己手动运行 `/create-verification-skill`。[验证结果并提交 PR](./06-verify-and-ship.mdx#create-a-project-verification-skill) 会深入讲解它的用法。

如果您是第一次用 pstack，建议选“是”。能自己检查结果的 Agent 会一直改到检查通过为止；不能自查的 Agent 则会把每次结果都交回给您手工核对。整本指南里，回报最高的就是这个验证技能。

接着，如果项目里还没有形式化验证技能，配置流程还会再问您一次，要不要用 [`/create-formal-verification-skill`](https://github.com/cursor/plugins/blob/main/pstack/skills/create-formal-verification-skill/SKILL.md) 生成一个。普通测试只能检查人想得到去写的那几种情况；形式化验证技能则会在划定的范围内穷举所有情况，检查代码的一条关键性质——比如“同一个任务绝不会同时跑两份”。如果您的代码涉及并发、重试、状态机或解析器，出 bug 代价很高，而普通测试又很难触及真正会出错的边界，那就选“是”。否则选“否”，以后需求变了再补跑也不迟。[验证结果并提交 PR](./06-verify-and-ship.mdx#prove-a-property-with-a-formal-verification-skill) 会详细介绍它。

配置完成后，请新开一段对话。模型规则只会对新会话生效。

## 控制好开销 {#keep-the-cost-in-check}

pstack 会在子代理和评审组上额外消耗 token，这是换取严谨度的代价。如果想少花一些，可以这样做：

- 重新运行 `/setup-pstack`，选一档更小的推理预算，或者换成更便宜的模型。主对话用强模型、写代码的角色用更便宜更快的模型，是一种很划算的搭配。
- 把某个角色设为 `auto` 或 `inherit-parent`，让它直接复用主对话的模型。
- 缩短评审组列表。列表里每多一项，就会多跑一个子代理。
- 把 `/poteto-mode` 留给确实需要严谨把关的活。一眼就能看明白的小改动用不着它。

## 跑通您的第一个任务 {#run-your-first-task}

挑一件真实但规模不大的活，像跟同事交代任务一样把它说出来：

<Tabs groupId="prompt-lang">
<TabItem value="en" label="English">

```text
/poteto-mode add a --json flag to this command. text output stays byte-identical. verify both.
```

</TabItem>
<TabItem value="zh" label="中文">

```text
/poteto-mode 给这个命令加上 --json 参数。普通文本输出要保持逐字节完全一致。两种输出都验证一下。
```

</TabItem>
</Tabs>

留意待办列表。排在最前面的几项，就是匹配到的 <Term tip="剧本：poteto-mode 里一类任务的固定步骤，例如 Bug fix、Feature">playbook</Term> 复制进去的步骤——对这条提示词而言，匹配到的是 Feature playbook。

接下来，您就像平时一样继续追问就行。如果想让 `/poteto-mode` 在整段对话里一直生效，请在 `/` 菜单中选中它后按 Option+Enter（Mac）或 Alt+Enter（Windows），而不是直接按 Enter。这会把它设为 <Term tip="Cursor 的自定义模式：把一个技能挂在整段对话上，每一轮都在上下文里">Custom Mode</Term>（详见 [Cursor 的 Custom Mode 文档](https://cursor.com/docs/skills#using-a-skill-as-a-custom-mode)），在您主动退出之前，它每一轮都会留在上下文里。Custom Mode 可以在 Agents Window 和 CLI 里使用。如果只是普通按 Enter，技能只会挂在当前这一条消息上，随着对话往后聊，它的作用就会逐渐淡出。
