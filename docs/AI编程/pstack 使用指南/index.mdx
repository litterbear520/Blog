# pstack 使用指南

<CourseHero lessonCount={10} sourceHref="https://github.com/cursor/plugins/tree/main/pstack/docs/guide" sourceLabel="pstack guide">

不再事无巨细地替 Agent 操心每一步时，pstack 才能发挥最大威力。您只需要说清楚想要什么，以及怎样才算完成。`/poteto-mode` 会挑选合适的 <Term tip="剧本：poteto-mode 里一类任务的固定步骤，例如 Bug fix、Feature">playbook</Term>，按步骤需要调用其他技能，最后把证据摆在您面前。本指南通过贴近日常开发的提示词，帮您养成这套工作习惯。

</CourseHero>

## 学习目标

1. 安装和配置 pstack：安装插件，并选定要使用的模型。
2. 用 /poteto-mode 分派工作：给出一个目标，看它如何挑选对应的 playbook。
3. 改代码之前先读懂代码：先做一次只读调查，再用 `/how`、`/why`、`/teach` 和 `/recall` 摸清现状，然后再动手改代码。
4. 写代码之前先做设计：在代码把形态定死之前，先用 `/architect`、`/arena`、`/swarm`、`/interrogate`、原型和计划敲定方向。
5. 实现改动并清理 diff：了解各类构建 playbook，以及 `/tdd`、`/unslop` 和 `/no-comments`。
6. 验证结果并提交 PR：在真实应用上证明改动有效，用形式化验证覆盖测试很少触及的角落，用 `/benchmark-checklist` 核查性能数据，然后提交一个范围集中的 PR，并一直推进到合并。
7. 睡觉时让工作继续跑：先建立信任再开循环，定好通宵运行的约定，保留可供事后审查的 <Term tip="决策日志：Agent 每做一个决定记一行，事后可以审查">decision log</Term>，并用 Cursor 的 Project 和自动化任务突破单个 Agent 的上限。
8. 用原则名引导 Agent：记住 24 条原则的名字，在任务中途一句话把 Agent 拉回正轨。
9. 打造您自己的版本：定制您自己的模式，用 `/correct` 纠正反复出现的错误，并学会怎样测试技能改动。
10. 常用配方与常见误区：拿来就能复制的提示词，以及值得提前避开的坑。

第一次阅读时，请按顺序读完这十章。读过一遍之后，每一章都可以单独拿来查阅。

遇到卡壳，或者拿不准该用哪个技能时，可以输入 [`/poteto-help`](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-help/SKILL.md) 并附上您的问题：

<Tabs groupId="prompt-lang">
<TabItem value="en" label="English">

```text
/poteto-help which skill should i use to review this branch?
```

</TabItem>
<TabItem value="zh" label="中文">

```text
/poteto-help 我应该用哪个技能来审查这个分支？
```

</TabItem>
</Tabs>

它会直接回答您，给您一段可以直接发送的提示词，并附上答案对应的技能或指南页面链接。它不会直接开工，因为跑一次 pstack 会实打实地消耗 token，所以等您准备好了再发那段提示词就行。`/poteto-help` 只在您亲自输入时才会运行，不会被自动调用。

## 如果您只记住一件事 {#if-you-only-remember-one-thing}

用您自己的话，给 Agent 一个目标和一个检查标准：

<Tabs groupId="prompt-lang">
<TabItem value="en" label="English">

```text
/poteto-mode the export writes duplicate rows when a retry lands mid-run. repro first, then fix and verify.
```

</TabItem>
<TabItem value="zh" label="中文">

```text
/poteto-mode 任务跑到一半触发重试时，导出会写入重复行。先复现，再修复并验证。
```

</TabItem>
</Tabs>

您不需要指名用哪个 playbook，也不用列出要调用哪些技能。“repro first”（先复现）加上一个可验证的结果，就足够让 `/poteto-mode` 判断该走哪个 playbook。它会自动匹配 Bug fix playbook，把步骤复制到待办列表里，并在每一步推进时调用对应的技能。
