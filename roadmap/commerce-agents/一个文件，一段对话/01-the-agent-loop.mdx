# 循环与第一个工具

一个购物助手不能只会介绍商品，还要能查询商店里实际有什么。这一节，我们从“店里有没有降噪耳机？”这个问题出发，为助手接上一个商品搜索工具，再把搜索结果交回模型，让它完成回答。

读完这一节，您将能够区分工具定义与工具函数，跟踪一次 `tool_use` 到 `tool_result` 的过程，并解释为什么一次工具调用通常需要不止一次模型请求。阅读代码只需要了解 Python 函数、字典、循环和 JSON；运行示例时才需要准备 API 密钥。

## 只会聊天还不够

模型知道什么是降噪耳机，不代表它知道这家店的商品目录。即使我们在提示词里写“你是一个购物助手”，也没有把商品的价格、评分和库存状态交给它。

我们需要让程序提供一项具体能力：根据关键词搜索商品。为了先看清调用过程，这里用六条示例商品组成的 `PRODUCTS` 列表代替数据库。它不是实时库存服务，但足以演示模型怎样取得原本不在对话中的信息。

这里的分工是：**模型提出搜索请求，Python 程序执行搜索，模型再根据搜索结果回答。** 模型生成了工具调用，并不等于函数已经执行。

## 一次搜索怎样完成

工具调用不是模型直接进入 Python 程序，而是应用与模型之间的一次往返。以查找耳机为例，这个过程可以分成四步：

1. 程序把用户问题和搜索工具的定义一起发给模型，说明有哪些工具、各自接受什么参数。
2. 模型需要商品数据时，返回一个 `tool_use` 内容块，其中包含工具名称、输入参数和这次调用的 ID。
3. 程序执行对应的搜索函数，把结果放进 `tool_result` 内容块，并用 `tool_use_id` 对应这次调用。
4. 程序带着更新后的对话再次请求模型。模型读到结果后，可以回答用户，也可以继续请求工具。

因此，搜索后还要再请求一次模型：**函数的返回值只有被加入对话并发送出去，模型才能看到。** 只把结果打印在终端里，并没有完成回传。

## 把一次调用放回整段对话

看过演练后，再从消息的角度看一次往返。下面是“一次搜索后直接回答”的结构示意，不是预录运行结果；真实模型可以请求不同参数，也可以发起多次搜索。

| 顺序 | 消息角色 | 消息内容 |
| ---- | ---- | ---- |
| 1 | `user` | 用户问：“店里有没有降噪耳机？” |
| 2 | `assistant` | 模型提出 `search_products` 调用，例如参数为 `{"query": "耳机"}`。 |
| 3 | `user` | 程序送回包含搜索结果的 `tool_result`，对应上一条调用的 ID。 |
| 4 | `assistant` | 模型根据商品数据组织回答。 |

第三条消息虽然使用 `user` 角色，却不是让用户再输入一次，而是程序按 Messages API 的格式提交工具结果。第二条消息也不能只保留可读文本：模型发出的工具请求必须留在对话中，后面的结果才有对应对象。

代码中的两个循环处理的是两件事。**外层循环等待用户的下一句话；内层循环完成当前这句话引发的模型请求和工具调用。** `messages` 在外层循环之前创建，所以后续追问仍然保留前面的对话。

这里的最小实现把所有非 `tool_use` 的停止原因都当作退出内层循环的条件，但退出不一定表示回答正常完成。`end_turn` 表示当前模型回合正常结束，`max_tokens` 则可能意味着内容被截断；后续完善程序时，还需要分别处理这些情况，并为工具执行增加参数校验、错误处理和调用次数上限。

## 在本地运行

通过代码区右上角的复制按钮取得完整代码，保存为 `agent.py`。在已激活的 Python 虚拟环境中安装依赖：

```bash
python -m pip install anthropic python-dotenv
```

这个代码快照配置的是 DeepSeek 的 Anthropic 兼容接口，不是 Anthropic 官方服务。在 `agent.py` 同目录新建 `.env`，把占位文字替换为该服务的密钥；不要把 `.env` 或真实密钥提交到仓库。

```bash title=".env"
ANTHROPIC_API_KEY=替换为该服务的密钥
```

SDK 的包名不决定实际请求哪家服务，代码中的 `base_url` 才决定请求地址。运行前请核对快照中的接口地址和 `model` 是否适用于您的账户；换用其他服务时，密钥、接口地址和模型名需要一起调整。

```bash
python agent.py
```

出现 `>>` 后，输入“店里有没有降噪耳机？”。观察终端中的 `[调用工具]` 和 `[工具结果]`：前者表示程序准备执行模型请求的搜索，后者是 Python 函数的返回值。模型读到结果后的回答会以 `AI:` 开头；它也可能在请求工具前先输出一段文字，所以看到 `AI:` 并不代表整个流程已经结束。

在 `>>` 后直接按回车可以结束对话。这里只关注请求、执行、回传这条链路，不要求模型每次使用相同措辞，也不要求每个问题都调用工具。

至此，我们已经有了一个能够查询商品并继续对话的助手。以后增加商品详情或购物车能力时，仍然沿用同一条循环：让模型提出请求，由程序执行，再把结果交回对话。
