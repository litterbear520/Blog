Commerce Agents

难度：中级5 课

从一个文件开始，一步步长成 Anthropic 的电商 Agent 参考实现：每一课都在上一课的代码上加东西，改动的部分按行标出来。

内容整理自 anthropics/commerce-agents

这条路线不是作者的真实开发历程，而是从最终仓库反向拆解出来的学习路线：从一个只会聊天的脚本开始，遇到问题就解决问题，代码长了就拆分。整条路线分为八个阶段，下图标出了我们当前所在的位置。

每一课的结构是固定的：先说明上一课留下的问题，然后用一个动画展示这一课的结构和一次运行示例，接着逐步查看代码的改动，最后解释为什么这样设计，并对应到下面的六条规则。

学习目标​

  • 理解一个 agent 的本体就是一个循环：调用模型、执行工具、把结果送回去
  • 从工具 schema、门控、围栏这些最小的机制开始，看每一条设计规则是被什么问题逼出来的
  • 跟着代码从一个文件长成一个包，理解拆分的时机和依据
  • 掌握提示词缓存、展示层工具、技能、记忆这些让 agent 从能用到好用的手段
  • 看第二个角色（商户 agent）如何催生出共享层，以及 Web 界面和多个垂直行业如何接入

六条规则​

仓库 CLAUDE.md 里的设计规则，路线上每次遇到都会引用回来。

#规则一句话第一次遇到
1一个模型拥有对话没有路由器，一个模型从头聊到尾循环与第一个工具
2静态提示词字节不变变化的数据放在缓存断点之后Stage C
3UI 是展示型工具调用模型调 present_products，服务端校验补全Stage C
4第三方内容是围栏数据围栏标签包起来，写操作校验来源Stage A
5核心是领域中立的行业差异通过扩展点加入Stage F
6每个机制只定义一次三条运行路径共享同一份工具和门控Stage F

前提条件​

  • 读过前言里的三篇文章，尤其是《高效商务 Agent 架构指南》
  • 具备 Python 编程的实际工作知识
  • 用过一次 Anthropic 的 Messages API，知道 messages 和 tools 参数是什么
